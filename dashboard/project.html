Onion Quality Assessment and Grading System

Image-assisted inspection and explainable size/quality grading prototype.

Full project report ↗
Prototype status: the public dashboard simulates the conveyor and uses manual grading inputs. It does not run an image model, read real sensors, or save records to a database.

OVERVIEW

Project objective

Design a computer-vision-assisted system that evaluates visible onion characteristics and assigns an explainable grade. The proposed system analyzes size, shape, color, spots, surface damage, and visible defects, then presents results and inspection statistics in a dashboard.

Image-based diameter requires a known scale or calibrated camera setup. Weight must come from a scale or supplied measurement. An ordinary RGB image cannot establish either value on its own.

PROCESS

Simple workflow

  1. Onion image
  2. Preprocessing
  3. Feature extraction
  4. Defect detection
  5. Quality assessment
  6. Grade
  7. Dashboard and report

A numerical quality score requires a documented formula and validation. Current demo output comes from explicit grading rules, not an AI score.

RULES ENGINE

Prototype grading rules

Apply rules in this order. These thresholds are project-provided prototype values, not a claim of compliance with a commercial standard.

GradeRule
RejectedRot/fungus detected or defect area greater than 25%.
A · High qualityDiameter ≥55 mm, weight ≥100 g, roundness ≥0.85, and defects ≤2%.
B · Good qualityDiameter ≥40 mm, weight ≥50 g, roundness ≥0.70, and defects ≤8%, after the Reject and A checks.
C · Average qualityDoes not meet all Grade A or Grade B conditions and is not rejected.

EVALUATION

How to test

  • Use onion-separated train, validation, and test data.
  • Report precision, recall, F1, and a confusion matrix by class.
  • Test A/B/C/Reject threshold boundaries and missing measurements.
  • Measure latency and manual-review rate on stated hardware.
  • Do not treat randomized simulation values as model results.

LIMITATIONS

Current boundaries

Surface images cannot identify hidden internal defects or certify food safety. Lighting, background, variety, image quality, and annotation consistency affect model behavior. A bounding box does not provide reliable defect-area percentage; that requires a validated segmentation or measurement method. Validate all thresholds against the intended market before operational use.
